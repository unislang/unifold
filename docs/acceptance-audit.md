# 1.0 acceptance evidence audit

This document is the resumable traceability register for the 34 acceptance criteria in
[`ARCHITECTURE_IMPLEMENTATION_PLAN.md`](../ARCHITECTURE_IMPLEMENTATION_PLAN.md#acceptance-criteria-for-10).
It prevents a green aggregate test run or a completed component catalog from being mistaken for
full 1.0 readiness.

Last reconciled: 2026-08-27.

## Status vocabulary

- **Proven locally**: the whole criterion has direct repository-controlled automated evidence. It
  must still be rerun in the final release matrix.
- **Partial**: meaningful evidence exists, but at least one named part of the criterion is absent or
  indirect.
- **External gate**: completion requires policy approval, named people, provisioned infrastructure,
  pilots, or manual evidence that cannot be manufactured by the repository.
- **Open**: no sufficiently direct implementation evidence exists yet.

External gates are not waivers. The project remains incomplete until they are supplied or the
architecture plan is explicitly revised through governance.

## Current execution order

The next repository-controlled work follows dependency order:

1. Finish and publish the preserved governed AI/Studio slice, including its policy, cancellation,
   requested-check, isolated-preview, apply, export, and browser evidence.
2. Bind Studio proposals to the existing collaboration/control-plane protocol and prove concurrent
   human/AI rebase, stale approval, conflict, disconnect recovery, and compensating undo.
3. Close cross-origin extension isolation and same-page multi-runtime isolation.
4. Add locale/pseudo-locale/RTL and the remaining layout/accessibility matrices.
5. Complete release packaging and provisioned-environment evidence after license, scope, service,
   pilot, manual-accessibility, and governance inputs are available.

## Final verification rule

Before marking 1.0 complete, every row must be **Proven locally** or have direct, approved external
evidence attached to this register. The final run must include `pnpm release:check`, the complete
Chromium/Firefox/WebKit matrix on the declared runner, public-registry consumer parity, provisioned
service drills, manual accessibility/security evidence, and pilot/reforecast approvals. Aggregate
test counts alone cannot change a row's status.
